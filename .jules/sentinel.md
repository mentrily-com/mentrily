## 2024-07-31 - [SSRF bypass via string matching and DNS TOCTOU]
**Vulnerability:** A highly critical Server-Side Request Forgery (SSRF) vulnerability existed in `WebhookProcessor` because user-supplied URLs were fetched directly using the native `fetch` API without any IP resolution or validation, exposing internal network infrastructure and metadata services.
**Learning:** Preventing SSRF requires deep protocol-level intervention. Relying on string prefix checks on IP ranges is brittle and easily bypassed via IPv6 configurations or IP parsing quirks. Furthermore, just validating the hostname is insufficient due to Time-Of-Check to Time-Of-Use (TOCTOU) DNS rebinding attacks, where an attacker changes the DNS record between the validation step and the actual connection. Additionally, overriding network dispatchers within a processing loop (like a BullMQ worker) without connection pooling rapidly exhausts sockets.
**Prevention:** Always intercept the connection phase directly (e.g. via `undici`'s `Agent`). Use `dns.lookup` to retrieve all A/AAAA records, and validate them with a robust library like `ipaddr.js` to ensure the range is strictly `unicast`. Then, explicitly bind the socket to the validated IP address rather than the hostname to completely eliminate DNS rebinding risks. Maintain connection pooling by instantiating the agent outside the per-job execution loop. For HTTPS, use `opts.servername || opts.hostname` for the SNI configuration to prevent TLS failures on ports.
