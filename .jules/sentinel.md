## 2024-08-09 - [Webhook Dispatcher SSRF Vulnerability]
**Vulnerability:** The webhook dispatcher logic in `backend/src/modules/webhook/webhook.processor.ts` used the native global `fetch` directly with user-provided webhook URLs. This exposed the application to Server-Side Request Forgery (SSRF) and DNS rebinding attacks, allowing an attacker to force the server to make requests to internal/private IP ranges (like `127.0.0.1` or `10.x.x.x`).
**Learning:** Native `fetch` lacks the ability to hook into the DNS resolution and connection stages. Simply checking the URL prefix (e.g. `!url.startsWith("http://127.0.0.1")`) is insufficient because attackers can provide a domain they control that resolves to an internal IP (or use DNS rebinding).
**Prevention:** Always implement SSRF protection by pinning the DNS resolution. We resolved this by using `undici` with a custom `Agent` `connect` method. The method uses `dns.lookup`, validates the resolved IP using `ipaddr.js` to ensure its range is `unicast` (rejecting private/multicast IPs), and then explicitly passes that exact IP to the underlying socket connection (`tls.connect` / `net.connect`) to prevent TOCTOU/DNS rebinding attacks.
