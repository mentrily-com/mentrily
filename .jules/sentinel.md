## 2026-07-24 - Fix SSRF Vulnerability in Webhook Dispatch
**Vulnerability:** The webhook processor (`backend/src/modules/webhook/webhook.processor.ts`) performed a `fetch()` using an unvalidated user-provided URL (`endpoint.url`). This allowed for Server-Side Request Forgery (SSRF), enabling an attacker to send requests from the backend to internal network resources (e.g., `localhost`, `127.0.0.1`, AWS metadata `169.254.169.254`, or private subnets).
**Learning:** Even if the webhook logic itself is simple (signing a payload and sending it), blind fetching user-provided URLs is dangerous. DNS-based bypasses (like `localtest.me` resolving to `127.0.0.1`) mean that simple string matching against the URL is insufficient to stop SSRF.
**Prevention:** Implement a robust SSRF validation utility that parses the URL, enforces HTTP(S) protocols, and explicitly resolves the hostname via DNS (`dns.lookup`) to verify that none of the resolved IP addresses are private, loopback, or link-local. Use this utility before any backend request to external, user-provided URLs.
