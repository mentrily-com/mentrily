## 2026-08-05 - SSRF Protection with undici and ipaddr.js
**Vulnerability:** Server-Side Request Forgery (SSRF) in webhook dispatcher.
**Learning:** The native `fetch` API doesn't provide a way to customize DNS resolution and connection lifecycle, making it difficult to prevent SSRF vulnerabilities like DNS rebinding. Replacing `fetch` with `undiciFetch` and providing a custom `Agent` allows hooking into the `connect` callback. However, when parsing hostnames from `opts`, it is critical to use `opts.hostname || opts.host` because `opts.host` may include a port number (e.g., `example.com:8443`), which breaks `dns.lookup()`. Also, `undici` expects the `connect` callback to be fired exactly once; multiple firings (like from multiple `connect` events) throw `InvalidArgumentError`.
**Prevention:** Use `undici` with a custom `Agent` for SSRF protection, validate `dns.lookup` inputs carefully to strip ports (`opts.hostname || opts.host`), and wrap the Agent's callback to ensure it's only called once. Always install workspace dependencies with the `--filter` flag from the root (e.g., `pnpm add undici ipaddr.js --filter backend`) to avoid massive `pnpm-lock.yaml` diffs and polluted roots.
